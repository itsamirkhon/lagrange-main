## Этап 6b — классификация документов, денежные проверки, X1 (ingest, часть B)

Замеры: `eval/ingest_eval.py sim --class-map eval/class_map.json` на `sim/worlds/L0..L4`, один и тот же снапшот симуляции до и после. Правка оценки: в `class_map.json` добавлено `irrelevant -> J1`
(без неё мусор L4 нельзя было засчитать верным), и `eval` задаёт дату расчёта `LAGRANGE_AS_OF` = конец `end_month` из `sim/config/world.yaml` (2026-10-31); для S1 в продукте по умолчанию берётся сегодняшняя дата.

Колонка «без имени файла» — честная оценка по содержимому: оставшиеся ошибки — только документы-картинки (JPG/PNG), у которых нет текста, потому что в этой среде нет языковых данных Tesseract
(`rus/uzb/eng` недоступны, OCR пуст). Для них единственный сигнал — слова в имени файла (`waybill`, `memo`, `carrier`, `junk`); уверенность такого результата 0.65 (ниже авто-принятия, идёт на проверку).
Префикс вида `D5_` классификатор намеренно не использует. Это измерение на одной синтетической корпусе, а не точность на реальных документах клиента.

**Что сделано**
- `ingest/classification.py`: взвешенные сигналы — заголовок документа (ru/uz/en, кириллица и латиница узбекского), шапка таблицы, ключевые слова тела, слова в имени файла; воздержание («unknown») при слабом или неоднозначном результате.
- `ai/classify.py`: необязательный путь LLM через единый клиент OpenRouter. `LAGRANGE_AI_MODE=openrouter` (нужен `OPENROUTER_API_KEY`, `LAGRANGE_AI_BUDGET_USD>0`) вызывает модель только при уверенности детерминированного классификатора < 0.85
  и записывает каждый ответ в кеш `<data>/cache/classification`; `LAGRANGE_AI_MODE=replay` читает только записанное; промах кеша не роняет пакет (остаётся детерминированный ответ, в `class_signals` — `llm_unavailable`).
  Модель — `classifier` в `config/ai.yaml`. Уверенность модели ограничена 0.85 (не откалибрована). Путь проверен только с поддельным транспортом (запись → воспроизведение); **реальных записанных ответов нет** — ключа не было, живой вызов не выполнялся.
  Изображения в модель пока не передаются (только текст и имя файла).
- `ingest/money_fields.py`: из страниц КП, договоров, сводок таможни и реестра строятся записи с цитатами; проверки C1 (цена без валюты), S1 (КП просрочено относительно `as_of`; выписка реестра заменена более поздней записью),
  C2 (в колонке «…UZS» значение с явной пометкой валюты в 100+ раз меньше медианы колонки), C3 (себестоимость без НДС ниже таможенной стоимости USD × курс). Всё — предложения на проверку, значения не исправляются.
- `api/ingest.py` (минимальный хук): классификатор, `as_of` (параметр `create_app`/`LAGRANGE_AS_OF`, пишется в пакет), запуск проверок при создании пакета; результат — `issues` и очередь проверки. Старый `scorer=` по-прежнему подменяет классификацию.
- X1 (`cross_document.check_quote_contract_moq`): у КП нет ссылки на договор, а имена поставщиков часто нечитаемы, поэтому связь неоднозначна. Правило: кандидаты — недрафтовые договоры с ценой в пределах 5%; MOQ КП помечается, только если он
  не совпадает ни с одним кандидатом, так что вывод верен при любой связи. Черновики («ПРОЕКТ/draft») не считаются.

**Пробелы**
- C1 в договорах (6 случаев) не виден в тексте, который получается после разбора; X1 не ловит КП на другие препараты (цены вне ±5% любого договора), т. к. у договора нет названия препарата.
- Остаются без прогресса: M1, X2 (кроме 3/10), V1, U1, A1 (2/10), R1–R4, N1/N2/L1 — это другие потоки; OCR-изображения требуют установки языковых данных Tesseract или LLM с изображениями.
- Курс ЦБ на дату ГТД (сетевая проверка C3) по-прежнему только через `/money-checks`; в пакете C3 определяется внутренним противоречием документа.
