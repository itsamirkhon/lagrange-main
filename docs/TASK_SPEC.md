# LAGRANGE Rx monorepo — постановка (для исполнителей)

Задача №16 Национального AI-хакатона (Ташкент): прибыльность импортёра рецептурного лекарства при референтных ценах, приказ Минздрава РУз №3735.
Цель: один репозиторий, где сквозной контур работает на настоящих данных симуляции:
документы → Ingest → подтверждение человеком → `ontology.ClientGraph` → двойник (калибровка) → оптимизатор → независимая проверка законности → оценка на истине симуляции.

Спецификации в `docs/`: PRICING_3735, CONTRACT_V2, SIMULATION, ONTOLOGY, INGEST, DECISION_ENGINE, SIMULATION_HANDOFF, CONCEPT_LAGRANGE_Rx. Журналы: `docs/WORK_LOG_ingest.md`, `docs/UB_LOG_sim.md`, `docs/README_*_legacy.md`.
Рабочий метод — `docs/UB_MODE.md` (сначала тест, маленькие шаги, Keep a Log, частые коммиты).

## Нерушимые правила
1. Граница продукта и симуляции. `src/lagrange_rx/**` не импортирует `sim` и не читает `sim/truth/**`, `sim/worlds/*/manifest.json`. `sim/**` не импортирует `lagrange_rx`. Истину и манифесты читает только `eval/**`. Проверяют `tests/test_boundaries.py`.
2. Одна модель мира: `ontology.ClientGraph` — единственный вход ядра. Двух Product/Route/SupplyOption быть не должно.
3. Один каталог правил `rules/uz_pharma_rules.yaml`; законодательные числа только оттуда по `rule_id`.
4. ИИ только через OpenRouter (`ai/openrouter.py`, `config/ai.yaml`, ключ `OPENROUTER_API_KEY`, не коммитить). В ядре ИИ нет. Тесты — без сети (записанные ответы).
5. Честность чисел: ни одного выдуманного результата. Каждое число в отчётах — из прогона со `snapshot_id`; синтетика, допущения, нереализованное помечаются явно. Пороги `eval/thresholds.json` не менять задним числом.
6. Неподтверждённое не идёт в расчёт (`for_calculation()`); законные ограничения никогда не ослабляются.
7. Git: ветка `integration/monorepo`; никаких force-push; исходные репо не трогать.

Каждый элемент подключён к реальному API, без заглушек с числами.

Известное по симуляции: в инвойсах нет цены за единицу; статьи расходов на английском в русской таблице; нет теста, что каждая порча M1 видна в документе.

## Как работать
- Тесты: `source .venv/bin/activate; python -m pytest <путь> -o addopts="" -p no:cacheprovider` (venv общий, Python 3.14). Полный прогон ядра ≈8 мин, `tests/sim` ≈7 мин — гоняйте только нужное.
- Каждый этап заканчивается коммитом, зелёными тестами и записью в `docs/MONOREPO.md` (что сделано, решения, тесты, что осталось).
- Правки в `sim/` допустимы только с перегенерацией и обновлением манифестов и сохранением границы.
