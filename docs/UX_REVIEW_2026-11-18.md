# LAGRANGE Rx decision-lab UI contract

Status: design implementation review (not a certified accessibility audit). Design direction: preserve current warm off-white / deep-green system, existing CSS variables, Russian seven-step workflow, and no-JS-framework frontend.

## Intent

A judge must be able to identify the data basis, confirm a useful business objective, operate the solver, and understand whether a decision is valid or impossible. A dashboard that paints `legal` green for a no-supply plan violates this purpose.

## Workflow and states

1. **Documents.** Distinguish uploaded, parsed, unverified, confirmed, missing, corrupt. Source and provenance stay attached to numerical values. Never treat model extraction as human approval.
2. **Understand.** Show source excerpts, document references, and unresolved fields. Do not fill unknown amounts with zero.
3. **Issues.** Show blocking data issues before confirm. Bulk approval of high-risk financial fields is not appropriate for real use; the existing button requires explicit confirmation, and pilot deployment needs field-level authorization and audit.
4. **Twin.** Display calibration target/actual with units and tolerances. If uncalibrated, label the reason and stop optimizer unless an explicit synthetic demo mode is used.
5. **Plan.** Default to an adjustable minimum expected supply of 90% as a **synthetic business assumption**; expected-profit objective is presented first. CVaR may reduce expected profit by design. Show the solver certificate only when the solver actually proved optimality.
6. **Shock.** Recompute against real backend state, do not chart an imaginary result. On impossible conditions, show the failed constraint set and controls that can be adjusted.
7. **Evidence.** Show code commit, snapshot, model-based legality status, and historical-vs-current result freshness. A zero-supply plan means legality **not evaluated**, not 100% passed.

## Accessible interaction contract

- Keyboard-accessible skip link, real buttons, visible focus indicators and status region for optimization.
- 390px and 1440px viewport smoke; no horizontal whole-page overflow. Tables may scroll within their containers.
- Text plus color for success/warning/error, not color alone.
- `prefers-reduced-motion` suppresses decorative transitions.
- Do not announce claim of WCAG conformance without keyboard and screen-reader review.

## Design tokens and CSS

Reuse `--bg`, `--surface`, `--ink`, `--muted`, `--line`, `--accent`, `--ok`, `--warn`, `--bad`, existing `--radius`. New classes implement provenance banner, service hint, presentation mode and skip link, without creating a separate style framework. Avoid arbitrary Golden Ratio rules and accidental 12px tap targets; controls target at least 40px height in this patch.

## Visual test matrix

- Wide desktop 1440x900; mobile 390x844; wide presentation toggle.
- Browser default light and dark appearance (light smoke automated; dark manual check outstanding).
- No graph selected; empty plan; infeasible plan; nonzero checked plan; failed numerical checks.
- Missing report, `all_pass=false`, solver timeout, malformed upload.
- UTF-8 Cyrillic layout and long monetary values, including negative and unknown values.

These are functional acceptance states, not decorative variants. Screenshots from `scripts/browser_smoke.py` are only part of the evidence.
